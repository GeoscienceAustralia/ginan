# 阶段 B E9：20 个独立站用户端 PPP/PPP-AR 验证结果

日期：2026-08-03  
分支：`codex/zhang-full-rank-ppp-rtk`  
产品：E9 GPS L1C/L2W，74 站估计，60 s，6 h  
用户：20 个未参与产品估计的独立站

## 1. 验证设计

20 个用户站为 MARS、DYNG、NICO、BREW、JPLM、BOGT、GLPS、POAL、DJIG、MBAR、SEY2、GMSD、USUD、CEDU、GAMB、MRO1、TONG、CAS1、DUMG、PALM。区域分布为：

- 欧洲/北大西洋 3 站；
- 北美/北极 2 站；
- 南美/加勒比 3 站；
- 非洲/中东/印度洋 3 站；
- 中东亚/南亚 2 站；
- 澳洲/太平洋 4 站；
- 南极/南大洋 3 站。

每站均独立启动 PEA，不与74站网络共享滤波状态、模糊度、协方差或图对象。运行4种模式：

1. `full_ar`：00:00--06:00，使用E9固定产品并进行LAMBDA；
2. `full_float`：00:00--06:00，使用同一E9固定产品，但关闭用户模糊度固定；
3. `restart_ar`：03:00独立初始化至06:00，进行LAMBDA；
4. `restart_float`：03:00独立初始化至06:00，关闭用户模糊度固定。

用户历元同步为60 s。LAMBDA只请求最优和次优两组候选；另设每信号最多8个最低方差候选的PAR安全上限。本次实际最大候选总数为16，PAR上限没有触发，因此没有人为删减本次可固定集合。

## 2. 完成情况

80个计划案例中77个完成：

- GLPS `full_ar` 超时；
- GLPS `full_float` 超时；
- USUD `full_ar` 超时。

其余完整弧段一般得到359--361个诊断历元；BOGT和DJIG有少量缺测，分别得到356和354个AR诊断历元。所有20站的03:00重启AR与float案例均完成。

单案例设置180 s墙钟上限。该上限远大于正常案例耗时，只用于阻止异常产品值导致单站永久阻塞整个批处理。

## 3. PPP/PPP-AR结果

- 完成的18个完整AR站中，坐标水平RMS小于10 m且高程RMS小于20 m的站数为0；
- 完成的19个完整float站中，同一门限通过站数也为0；
- 9个完整AR站出现固定，共67个新固定整数；
- 19个有固定事件的位置检查中，6个事件在固定时已超过0.5 m水平或1.0 m高程门限，错误位置代理率为31.6%；
- 03:00重启后，18站发生巨大数值发散；DYNG和CEDU的AR/float位置误差在全部历元精确保持0，代表位置状态没有产生有效更新，不能当作厘米级结果；

## 4. 统一失效时间

在产品异常前，多数float用户能够达到分米至厘米级瞬时误差。例如MARS在01:52的水平误差约0.059 m、高程误差约0.061 m；DYNG在01:56的水平误差约0.016 m、高程误差约0.043 m。

19个完成的完整float站全部在02:04首次出现超过10 m水平或20 m高程的失效，其中18站在该历元直接超过1 km水平或2 km高程。各站在同一历元同步失效，排除了单站观测质量或区域几何是主因。

## 5. 卫星产品数值连续性审计

02:03至02:04，E9固定产品的卫星改正发生大幅跳变：

- 所有卫星/信号改正步长中位数约2.37e5 m；
- 当时仍标记为 `integer_valid` 的产品步长中位数约2.21e5 m；
- G09 L2W改正单历元最大跳变约1.486e7 m；
- datum version和discontinuity counter仍全部为0。

随后数值继续发散：

- 02:20首次出现超过1e12 m的整数有效改正步长；
- 02:21首次出现超过1e30 m的整数有效改正步长；
- G18 L2W最大绝对改正达到9.379e39 m；
- G18 L2W最大相邻历元步长达到9.469e39 m，仍被标记为 `integer_valid`，datum version=0，counter=0。

因此，E9虽然通过了“整数关系结构连续性”检查，但卫星钟差/相位组合的数值状态已经失稳。`integer_valid` 当前只表示整数格结构、datum关系和形式精度门限通过，不代表产品改正值在物理量级上连续或可供用户使用。

## 6. 根因判断

本次20站验证否定了“消除持久关系冲突即可得到可用产品”的假设。当前主要阻塞已经转移为卫星产品数值状态失稳：

1. 持久整数datum约束住了整数关系，但没有约束每历元卫星钟差和相位偏差的数值传播；
2. 02:04发生卫星相关、非公共的数十公里至千万米跳变，不能由一个用户接收机钟状态吸收；
3. 产品数值跳变没有触发datum version、discontinuity counter或 `integer_valid=false`；
4. 用户端同时把 `clock_m` 用于码观测、把 `correction_m=clock_m-phase_m` 用于相位观测，因此float和AR都同步崩溃；
5. 部分固定事件是在产品已经错误后发生，属于错误固定，固定数量和固定率不具备正面意义。

该失败不是20个验证站数量不足，也不是全球测站联合估计本身导致；独立站的全球同步失效反而把问题定位到了共同使用的卫星产品。

## 7. 验收结论

E9未通过以下任何科学验收项：

- 完整弧段float坐标完整性：失败；
- 完整弧段PPP-AR坐标完整性：失败；
- AR相对float改善：失败；
- 03:00独立重启可重复性：失败；
- 产品数值连续性：失败；
- 20站完整可处理性：失败，3/80案例超时。

当前产品不得进入24 h扩展或对外Bias-SINEX/SSR输出。

## 8. 下一步修复顺序

1. 在产品写出前增加卫星钟差、相位项和组合改正的相邻历元物理连续性门限；超限必须令产品无效并增加IOD/counter，不能继续保持 `integer_valid`。
2. 分离“整数datum连续性”和“浮点数值状态连续性”，分别输出状态与失效原因。
3. 检查02:03--02:04网络滤波状态、钟差datum、接收机钟/卫星钟耦合以及持久分量扩展后的协方差更新，定位首次2.21e5 m中位跳变来源。
4. 用外部WUM CLK对每颗卫星的网络钟差作逐历元差分，区分公共钟差datum平移和卫星相关发散。
5. 修复后先重跑02:00--02:10短窗，要求所有整数有效产品相邻历元改正处于物理可接受量级，再重复20站float；float完整性通过后才恢复AR和重启验证。
