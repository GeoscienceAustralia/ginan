# 阶段 B E11：当前结果分析、实施计划与文献审查

日期：2026-08-03
分支：`codex/zhang-full-rank-ppp-rtk`

## 1. 当前结果的因果分析

### 1.1 已经解决的问题

E10 证明纯 float 权威网络滤波器与一次性 fixed 分支的隔离有效。74 站、00:00–02:10、131 个 60 s 历元中：

- FLOAT 7860/7860 行均为数值有效、连续且可供 PPP 使用；
- FLOAT 最大相邻历元产品变化为 26.2878 m；
- FIXED 最大相邻历元产品变化为 26.2245 m；
- 两个分支均无大于 1000 m 的跳变；
- E9 在 02:04 出现的 \(10^5\)–\(10^7\) m 跳变以及后续 \(10^{39}\) 量级发散没有复现。

因此，E9 的直接失效链已经被切断：历史 held/new 整数伪观测污染权威滤波状态，才导致共同产品在所有用户站同步失效。74 个估计站、全球联合组网和 60 s 历元不是该数值爆炸的直接原因。

### 1.2 E10 尚未解决的问题

E10 fixed 分支只有 3480/7860 行 `branch_valid=1`，全部 7860 行 `pppar_usable=0`。剩余问题分为三层。

第一层是事务边界错误。02:04 的 held 和宽巷/第一阶段整数约束通过，但下一阶段 NIS=72.7308，高于阈值 46.863。当前代码把整个历元作为一个事务，导致后一级失败连带回滚前一级已通过结果。

第二层是固定对象与产品台账对象不一致。`rankAwareGnssAr()` 能固定整数线性组合，但持久卫星产品需要的是明确的逐星关系，例如：

\[
G_{s,j}-G_{r,j}=k_{sr,j}\in\mathbb Z.
\]

E10 虽然在许多历元固定了 5–13 个组合，但 `recoverNamedTargets()` 只有 00:22、00:55 等少量历元恢复出具名目标，且达不到连续 5 个历元的提升条件。因此：

- `current_alignment_state`：7860/7860 均为 `CURRENT_ALIGNMENT_PENDING`；
- `integer_datum_continuous`：0/7860；
- `integer_precision_valid`：0/7860。

这说明“固定了多少整数线性组合”不能直接替代“形成了多少可供卫星产品使用的具名整数关系”。

第三层是产品有效性语义不完整。当前 `writeZhangInternalProducts()` 仍以全局 `integerDatumComplete` 调用 `markFixed()`，而这个全局量由

```text
heldIntegerRank == 全部 ambiguity 状态数
```

决定。对于 PAR 和分层宽巷/窄巷固定，这个判据不成立；产品应按卫星、信号、当前 phase segment、持久关系和稳定期分别判断。

### 1.3 不能采用的“快捷修复”

- 不能把 NIS 阈值放宽到足以接受 72.73；这会把统计不相容伪装成可用整数。
- 不能把 `promotion_confirmation_epochs` 从 5 降为 1；一次偶然固定不足以建立持久产品 datum。
- 不能继续用全状态 ambiguity 数量定义产品整数有效性。
- 不能在当前 `KFState` 不支持交叉过程噪声时直接改为 `C/Q` 动态状态。
- 不能在 `pppar_usable=0` 时直接扩展 20 站 PPP-AR，并把“没有固定”当成新的科学结论。

## 2. 详细实施计划

### P1：分层子事务

将同一历元的 fixed 分支拆为：

```text
权威 FLOAT
  -> HELD 基线事务
      -> WL 子事务
          -> L1/NL 子事务
```

规则：

1. HELD 失败时 fixed 分支不可用，但 FLOAT 不受影响；
2. WL 失败只回滚 WL，不影响 HELD 基线；
3. L1/NL 失败只回滚 L1/NL，保留已提交 WL；
4. 每个子事务只有在精确条件化、NIS、闭合、有限性和协方差检查全部通过后才提交；
5. 只有已提交子事务的整数行可以追加到持久物理弧 HNF。

### P2：具名产品目标 PAR

对 `PRODUCT_TARGET_WL_L1` 不再以不透明的 LAMBDA 组合直接驱动产品台账。先保留原始具名卫星目标，再按以下门限选择可固定子集：

1. 目标行在当前基本环坐标中精确可映射；
2. 目标协方差具有正条件方差；
3. 单目标整数舍入距离和整数错误概率通过现有 `ROUND` 门限；
4. 选中目标整体通过精确条件化 NIS；
5. 同一具名关系连续 5 个历元给出相同整数，才提升到持久台账。

宽巷先固定：

\[
G_{s,WL}-G_{r,WL}=k_{sr,WL}.
\]

在 WL 已提交的分支上固定第一信号：

\[
G_{s,1}-G_{r,1}=k_{sr,1},
\]

然后才允许推导第二信号：

\[
k_{sr,2}=k_{sr,1}-k_{sr,WL}.
\]

L1/NL 子事务失败时，WL 可保留用于下一历元统计和诊断，但不得把 L1/L2 标记为 PPP-AR 可用。

### P3：逐产品有效性

每条卫星—信号产品以如下条件判定：

\[
\text{integer valid}_{s,j}=
\text{structure valid}_{s,j}
\land
\text{persistent relation confirmed}_{s,j}
\land
\text{current alignment valid}_{s,j}
\land
\text{stabilization complete}_{s,j}
\land
\text{fixed branch valid}.
\]

不再要求全网络所有 ambiguity 状态均被 fixed。FLOAT 产品只能 `ppp_usable`，不能 `pppar_usable`。

### P4：held 冲突隔离与重新捕获

P1–P3 通过后，再处理 held 整体 NIS 的 10 次拒绝：

1. 对 rejected held 集合计算秩揭示白化残差；
2. 按物理弧关系或图连通块定位冲突行；
3. 只把冲突块置为 `REACQUISITION_PENDING`；
4. 未受影响的 held 块继续条件化；
5. 冲突关系连续 3–5 个历元兼容后恢复；
6. 不采用逐行独立检验后全部施加，因为这会破坏联合误警概率控制。

### P5：实验门禁

#### E11 短窗门禁

- 00:00–02:10 全部 131 历元完成；
- FLOAT 仍为 7860/7860 `ppp_usable`；
- 无大于 1000 m 的产品跳变；
- L1/NL 拒绝不得使已通过的 WL 或 HELD 分支整体失效；
- `FIXED_TRANSACTION_ABORTED` 应只来自 HELD 基线失败；
- 必须出现连续确认后的具名卫星产品分量，否则停止，不进入 6 小时实验；
- 至少有部分产品达到 `pppar_usable=1`，且不能通过降低确认历元或放宽 NIS 实现。

#### 6 小时网络门禁

仅在 E11 通过后运行：

- 361 个历元完整；
- FLOAT 零数值发散；
- fixed/PPP-AR 产品可用率按卫星、信号和图事件统计；
- 每次 IOD、datum version 和重新捕获均可追踪；
- 与 WUM CLK 比较去公共量后的逐星钟残差。

#### 20 站用户门禁

仅在 6 小时网络门禁通过后运行：

1. 20 站完整 float；
2. 03:00 独立重启 float；
3. 完整 PPP-AR；
4. 03:00 独立重启 PPP-AR；
5. AR 与同历元 float 坐标差、错误固定代理和可重复性检查。

固定率不是单独验收指标；坐标完整性、重启一致性和 float 对照必须同时通过。

## 3. 过往实验与论文审查

| 证据 | 对计划的支持 | 审查结论 |
|---|---|---|
| E9 20 站实验 | 所有 float 用户在 02:04 同步失效，产品先发生卫星相关巨跳 | 支持纯 float 权威分支和产品失败关闭；不支持增加站数或历元作为首要修复 |
| E10 74 站实验 | 纯 float 稳定，后级 NIS 拒绝导致整历元回滚 | 支持分层子事务；反对放宽 NIS |
| [Zhang et al., 2022, PPP–RTK functional models](https://link.springer.com/article/10.1186/s43020-022-00064-4) | 用 S-basis 构造 UDUC PPP-RTK 满秩模型并明确可估参数 | 支持当前生成树/基本环满秩结构；不直接证明软件事务策略，也不解决动态交叉过程噪声 |
| [Yan and Zhang, 2022, three-frequency PPP-RTK with PAR](https://doi.org/10.3390/atmos13071014) | 可靠子集优于强制全固定 | 支持部分提交，但其用户端 PAR 不能原样替代服务器具名产品目标 |
| [Zhang et al., 2024, multiple integer candidates](https://link.springer.com/article/10.1186/s43020-024-00141-w) | PAR 可以固定整数向量的线性组合，FAR 是 PAR 特例 | 支持保留任意已验证整数层；同时说明“不透明组合固定”和“具名卫星产品关系”是两个不同问题 |
| [Teunissen, 2025, ambiguity-resolved detector](https://link.springer.com/article/10.1007/s00190-024-01885-8) | 区分 float、整数映射、fixed 解和模型检验；强调高成功率与递归模型验证 | 支持事务式 fixed 副分支和独立检验，不支持仅凭 fixed 数量宣称可靠 |
| [Jeong et al., 2026, recursive batch PPP-RTK](https://doi.org/10.11003/JPNT.2026.15.2.145) | epoch-by-epoch AR 容易受未建模误差影响，累积多历元信息可提高稳定性 | 支持连续 3–5 历元确认和重新捕获；其用户端 SD 模型不能直接证明本网络台账实现 |
| [Zhou et al., 2026, entropy-weighted MPAR](https://doi.org/10.3390/s26144388) | 使用方差、残差和信号质量选择可靠具名 ambiguity 子集 | 支持具名目标 PAR；E11 先用已有方差、舍入距离、错误概率和 NIS，后续再评估多因子排序，避免一次引入过多不可归因变化 |
| [Li et al., 2026, Gaussian overbounding for PPP-RTK AR](https://doi.org/10.1016/j.asr.2026.01.099) | 重尾误差和低估随机模型会提高漏检和错误固定风险 | 反对放宽 NIS；后续应检查残差尾部并考虑 overbound，而不是把高 NIS 当成阈值太严 |
| [Lu et al., 2026, SSR product monitoring](https://link.springer.com/article/10.1186/s43020-026-00195-y) | 联合使用 PPP float ambiguity 偏差和相位残差能降低错误固定并提高产品监测可靠性 | 支持 FLOAT 完整性监测与用户端独立验证；说明只看 fixed 残差会漏掉固定前的稳定/慢变产品错误 |

### 文献审查后的修改

原计划仅提出“WL 成功就提交、L1 失败只回滚 L1”。审查后增加两项强制要求：

1. 子事务提交对象必须是具名卫星产品关系或能够精确恢复为具名关系的整数格，不能只记录 `nfix`；
2. E11 不改变 NIS 显著性水平和 5 历元提升条件。若可用率仍不足，应审计随机模型和具名子集质量，而不是降低可靠性门限。
